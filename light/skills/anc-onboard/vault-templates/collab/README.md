# 协作规范(人与多个智能体共用本 vault)

目标:让多个智能体与同事并行完成调研、整理、分析、复核与方案编制,同时保证来源可追溯、文件不互相覆盖、结论有人负责。只维护三份文件:`任务看板.md`、`决策记录.md`、`交接模板.md`,不增加别的表单。

## 单一事实来源

- 当前任务状态:`collab/任务看板.md`
- 已确认的协作取舍:`collab/决策记录.md`
- 原始访谈 / 原件:各业务目录的 `_originals/`
- 正式审批与签字:公司 IM(飞书 / 钉钉 / 企微),不在 vault 里

同一事实只保留一个原始来源,其余文档用链接引用。

## 角色

- 任务发起人:明确目标、范围、交付物和最终确认人。
- 主控(人或 devbot):拆分任务、维护依赖、收敛跨部门结论。
- 执行智能体:只修改任务指定的文件或目录,提交证据和未决问题。
- 复核人:检查证据、事实、专业边界和交付完整性。
- 部门责任人:确认本部门事实、基线和专业结论。

## 三条硬纪律

1. **一个文件同一时间只有一个主责。** 需要改他人主责文件时,先在看板交接主责或拆出新任务。
2. **原始逐字稿只追加勘误,不改写。** 整理后的判断进分析文档,并注明来源。
3. **vault 里的「已完成」不等于项目验收。** 需要审批或签字的结论在 IM 完成,再把确认人与日期回填到文档。

## 流程

1. 主控在看板新增任务,划定输入、输出和允许修改的文件。
2. 执行者领取后把状态改为「进行中」。
3. 先引用证据,再形成判断;不确定的内容标「待确认」。
4. 完成后按 `交接模板.md` 写交接记录。
5. 复核人检查后退回或改为「已完成」。
6. 涉及跨部门取舍、口径变化或目录调整时,追加到 `决策记录.md`。

状态只用五个词:`待领取`、`进行中`、`待复核`、`已完成`、`阻塞`。

## 证据与复核

- 每条关键判断至少指向逐字稿、历史文件、数据表或正式流程之一。
- 口头估计与实际统计分开标记。
- AI 生成内容由责任岗位人工复核;人工内容可由 AI 做完整性、一致性和格式检查。
- 工程、质量、法规、采购、商务等专业结论不得由智能体自行定案。
